## はじめに

6月30日の夜に `create-expo-app` を叩いて、7月29日に「推しスキ」がApp Storeに並びました。ちょうど30日です。

![推しスキのホーム画面](/images/06-home.png)
*ホーム画面。推しが画面いっぱいに出ます*

推し活アプリです。地下アイドルのライブや特典会の予定を1つのカレンダーにまとめて、忘れないようにするためのもの。スペイン人の私が、日本語で、日本の推し活のために作りました。開発もデザインもマーケティングも一人です。

この記事は「30日で作る方法」ではありません。間に合わせるために何を捨てて、何で死にかけたかの記録です。いちばん死にかけたのはコードではなく、Google Playの審査要件でした。

## 3ヶ月前、Xで「作る」と言ってしまった

推しが1人から2人になって、予定が管理できなくなりました。「そういうアプリを作ろうと思う」とXに書いたら、思っていたよりずっと反応がよくて、「使いたい」と言ってくれる人がたくさんいました。

![3ヶ月前の「作ります」の投稿](/images/00-original-promise.png)
*3ヶ月前の投稿。6,500インプレッション。スレッドで作る機能まで並べてしまいました*

それで本当に作ることにして、まずWebで動くプロトタイプを組んで、言ったことが技術的に可能かを確かめました。名前もXでアンケートを取って決めました。「推しスキ」はそのとき選ばれた名前です。

作ると宣言して、名前まで一緒に決めてもらった。もう後戻りはできません。私は約束を破らない人間ですし、なにより推しに見られています。恥ずかしい真似はできません。

## それから2ヶ月、ほとんど進みませんでした

現場に行っていたからです。とくに新しい推し・鈴音ひとみさんの生誕祭に全力を注いでいて、開発はほぼ止まっていました。

生誕祭が終わって我に返ったとき、自分の誕生日までちょうど30日でした。

## 締切を自分で作った

誕生日にリリースする。そう決めました。話題としても強いし、なにより日付を決めないとこのアプリは永遠に出ないと分かっていたからです。

自信もありました。以前やっていたITコンサルの会社で、30日でアプリを作ったことは何度もあります。できるはずだと思っていました。

甘かったです。**30日でアプリを作るのと、週40時間働きながら現場にも行きつつ30日でアプリを作るのは、まったく別の競技でした。**

この1ヶ月で、行くはずだった現場をいくつも諦めました。松山あおいさんはほぼ1ヶ月ぶりで、久しぶりに行ったら新曲のコールがファンの手でとんでもなく進化していて驚きました。私がいない間に現場は進んでいました。

## 最大の誤算：ボトルネックはAppleではなくGoogle Playだった

開発を始める前、いちばん最初に考えたのは「そもそもストアが期日までに承認してくれるのか」でした。

そしてAppleがボトルネックになると思い込みました。初日に年間のDeveloper Programを払って、審査に必要なものを全部先に確認しました。

本当のボトルネックはGoogle Playでした。気づいたのは残り16日、7月13日でした。Google Play Consoleを開いて、個人開発者アカウントには「**12人以上のテスターで14日間のクローズドテスト**」が必要だと知りました。

残り16日。テストに14日。余裕は2日です。

## Xに助けられました

その日から「テスターを緊急で募集しています」とXに投稿し続けました。

反応が信じられませんでした。知り合いに声をかけてくれる人、リポストしてくれる人が次々に出てきて、その1投稿が5000インプレッションまで伸びました。開発15日目のアプリの投稿です。数時間でテスターは集まりました。

![テスター募集の投稿](/images/03-tester-recruit.png)
*「12人×14日間のテストが必須です」。この投稿でテスターが集まりました*

ただ、集めて終わりではありませんでした。テスターのリストに入っても、Google Playの反映まで数時間かかるので「ダウンロードのリンクが押せない」という人が続出します。その1件1件に返信して案内するのも、その日の仕事でした。

その日は同時にこれをやっていました。

- ストアの申請フォームを全部埋める
- スクリーンショット用のAI画像を生成する
- デモ用のアカウントとダミーデータを作る
- **ログインとオンボーディングをその日のうちに実装する**（それまでログイン画面すら無かった）
- テスター希望者への返信

そして8時間の本業もありました。地獄でしたが、その日の終わりには「Androidのリリースは救った」と思っていました。あとで、それだけでは足りないと知ることになります。

## 作り方：サウナとClaudeと、動くモック

何を作るかを決めるのはサウナでした。週に何度か行って、頭を空にすると考えがまとまります。アイデアはほぼ全部そこで出ました。

実装はこの順番でした。

1. **オープンソースのテンプレートを探す。** ゼロから組む時間を機能に回すためです（Expo SDK 54 / React Native 0.81.5 / expo-router 6 / better-auth / zustand / TanStack Query / zod / MMKV / FlashList）
2. **バックエンドもログインも無視して、画面だけ作る。** まずは触れるモックが欲しかった
3. **Claudeにアイデアを並列で投げ続ける。** 完成度は後回しで、とにかく「何かが動く最初の版」を出す
4. 画面が最低限できてから、機能の細部を詰める

デザインを考える余裕は、この段階ではまったくありませんでした。

初日、サウナの帰りに、まずLovableで高速にプロトタイプを組んでXに上げました。反応を見るためです。**そこで学んだのは、Xの人はリプライを書かない**ということでした。数字は見てくれる、でも言葉はほとんど返ってこない。

![初日にLovableで作ったプロトタイプの投稿](/images/01-lovable-prototype.png)
*開発初日（残り29日）。Lovableのプロトタイプを上げて反応を見た。インプレッション344、リプライ1件*

そのモックから決まったのが、ホーム画面いっぱいに推しが出るガチャのキャラ画面みたいなデザインです。元ネタは大好きなゲーム『ネコぱら セカイコネクト』です。

## Xの数字で軌道を確認していた

| 残り日数 | 投稿した内容 | インプレッション |
| --- | --- | --- |
| 29日 | Lovableのプロトタイプ | 344 |
| 22日 | ホーム画面（デザインはまだひどい） | 1,000 |
| 19日 | 推しが話しかけてくるホーム | 1,800 |
| 18日 | oshisuki.com のランディング公開 | 879 |
| 17日 | ロゴのアンケート | 460 |
| 15日 | テスター緊急募集 | 5,000 |
| 当日 | リリース告知 | 7,200 |

伸びない日もあります。ランディングもロゴのアンケートも、時間をいちばんかけた割に数字は出ませんでした。**動いたのは「助けてほしい」と言ったときと、「出しました」と言ったときだけ**です。

ランディングを作った土曜日は、起きてから寝るまで丸一日それだけをやりました。AIでキャラクターを2体——ヲタとアイドル——作って、あとで好きなポーズを作れるようにして、配色を何十回も試して。出来上がったものを見て「これは成功する」と本気で思いました。

翌日には正気に戻りました。残り17日、まだ誰も私のアプリを触っていない。ランディングがきれいでも、インストールされる保証はどこにもない。それだけは絶対に避けたい。推しの顔を見られなくなります。

そこでロゴを作りました。AIで何十案も出して4つに絞って、Xのアンケートで投票してもらいました。いちばん票が集まった案が私の好みとも一致したので、そのまま採用です。

![ロゴのアンケート](/images/02-logo-poll.png)
*4案でアンケート。Aが60%でした*

最初はWebだけに使うつもりでしたが、気に入りすぎてアプリのアイコンにもしました。

そのあと、アプリ全体をWebと同じブランドで作り直しました。1日で全画面です。正直まだ相当ひどい出来でしたが、時間がなく、とにかく速く回すしかありませんでした。

## 自分のアプリのスクショが恥ずかしかった

Androidのテスト版を出したあと、テスターになってくれた人たちが自分のホーム画面のスクショをXに上げてくれました。

見て恥ずかしくなりました。開発15日のアプリなので当たり前なのですが、当たり前で済ませるわけにはいきません。そこからまた狂ったようにデザインを直しました。Xでは「どっちのデザインが好き?」のアンケートを回して、判断を自分ひとりで抱えないようにしました。

途中、「アプリはもっと振り切ってほしい、インストールするのが恥ずかしいくらいでいい」と言われて、この日程でゲーミフィケーションを足しました。あらゆる操作にポイントがついて、ヲタクとしてのランクが上がって、トップヲタを目指せる仕組みです。正気ではないですが、あれは入れて正解でした。

## Googleカレンダー連携を、Google APIを使わずに解決した

いちばん要望が多かった機能が「Googleカレンダーと連携してほしい」でした。

Google Calendar APIを使うには、Googleの審査が要ります。前の会社では2ヶ月待ったことがあります。残り6日で選べる道ではありません。

解決策は、**スマホ本体のカレンダーに書き込む**ことでした。iOSにもAndroidにも標準のカレンダーがあり、そこにGoogleアカウントを繋いでいる人が大半です。つまり端末のカレンダーに現場を書けば、Googleカレンダーにも出ます。OAuthも審査もいりません。

これで助かりました。「そのAPIを使わずに同じ結果を出す方法はないか」と考えるのは、締切が近いときにいちばん効く問いだと思います。

## 最後の関門は、自分ではどうにもできない審査だった

残り6日でiOSに提出しました。審査は「最大48時間」と書いてありますが、信じてはいけません。

**この記事を書いている今、アップデートの審査待ちが1週間目に入っています**。あのときこれが起きていたら、1ヶ月の努力ごと打ち上げを落としていました。運が良かっただけです。

残り5日からは、開発ではなく着地の準備をしました。Webにカウントダウンを置いて、リリースの瞬間に紙吹雪が出るようにして、毎日更新して。Xの投稿も全部先に書きました。

## 当日

誕生日でした。

朝に誕生日の投稿、昼に「18時にリリースします」の投稿、リリースと同時に「24時間限定、推しのホーム画面を見せてくれた人の現場を全部アプリに入れます」というキャンペーン、そしてリリース告知。リリースの投稿は7,200インプレッションまで伸びました。

![リリース告知の投稿](/images/07-launch-post.png)
*リリース告知。7,200インプレッション、リポスト21*

そのあと居酒屋で祝って、その日はちょうど推しのライブがありました。会場で誕生日を盛大に祝ってもらいました。

翌日、App Storeで「推し」と検索したら、レビュー900件超のアプリより上に自分のアプリが出ていました。あれはさすがに震えました。

![App Storeで「推し」と検索した結果](/images/05-appstore-search.png)
*リリース翌日。レビュー903件のアプリの上にいました*

初日を終えた時点で、登録ユーザーは55人。**Androidはまだ出ていない状態での数字です。**

![Android版が遅れることを告知した画像](/images/04-android-delayed.png)

14日間のテストは間に合わせたのに、その先の審査が間に合いませんでした。Android版が出たのは、8月7日です。

## 諦めたもの

いちばん痛かったのは、3ヶ月前に「作る」と言った機能を、リリース日に出せなかったことです。

- **カレンダーからの取り込み**（すでに自分のカレンダーに書いてある現場を、アプリに持ってくる）
- **メールからの取り込み**（チケットの当選メールから現場を作る）

メールからの取り込みは、あのスレッドにそのまま書いた機能です。カレンダーからの取り込みは書いてはいませんが、Googleカレンダーとメールの話をしておいて取り込みだけやらない、というのは自分の中では通らない話でした。どちらも、待っていてくれた人がいるのに当日は間に合いませんでした。

カレンダーからの取り込みは、リリースから10日後のアップデートでようやく出せました。メールからの取り込みはまだです。いま作っています。

そのほかに落としたものです。

- ウィジェット
- ユーザーが告知ページのURLを送って、自動で取り込めるようにする機能
- AIチャットがちゃんと動くこと
- アルバムの写真枚数を無制限にすること
- UXの磨き込み全般（いちばん大きい）

結局のところ、「使える」と言える最低限だけを出しました。完成したとは口が裂けても言えません。1ヶ月はまったく足りていません。

## それでも30日で出してよかったか

よかったです。

1ヶ月で出したから、**この製品が本当に受け入れられるのかを、何年も溶かす前に確かめられました**。もし半年かけて作っていたら、その半年は誰の反応も無い状態で作り続けることになっていました。

いま私がやりたいのは、残っている山ほどのUXの問題を直していく間、ユーザーに付き合ってもらうことです。そのために、数字も失敗もそのまま出していきます。
